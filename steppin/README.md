# steppin~

A JavaScript / Web Audio port of a Max/MSP generative drum patch (462 objects). It came as a compressed
`begin_max5_patcher` block. Open `index.html` in a browser, press **Start**, and drag the bars.

## Files

- `index.html` is the playable page. It's self-contained and generated by `build.py`.
- `src/dsp.js` is the audio engine. It runs one sample at a time inside an AudioWorklet, with a ScriptProcessor fallback.
  Each `phasor~` and `cycle~` from the patch is a state variable named after its Max object id (`p431`, `c250`, …).
- `src/app.js` covers the UI: transport, the canvas multisliders, sample loading and the engine bridge.
- `src/page.html` is the page template. `python3 build.py` inlines the two scripts into `index.html`.
- `src/test.js` renders 20 s offline and prints the peak, RMS and NaN count for the mix and for each voice soloed:
  `node src/test.js src/dsp.js`.
- `patch/decoded_patch.maxpat` is the decoded original. It opens in Max.

## Extras beyond the patch

- **Randomise** (R) re-rolls everything. **Alter** (A) nudges every value from where it is.
- **Presets**: 8 slots stored in the browser's localStorage. Click a slot (or press 1–8) to recall it. Shift-click a slot, press Shift+number, or press Save and then a slot to store the current sound.
  Export downloads `steppin-presets.json`, and Import loads that file back.
- **Reverb**: a stereo convolution reverb (generated noise impulse) on the master, with mix, size, tone and pre-delay. A limiter follows it.

## How the patch works

Every drum is a `phasor~` used two ways. `log~ → *~ → abs~ → *~ 32 → -~ 1200 → clip~` gives the
pitch sweep for a `cycle~`, and `1 − ramp` gives the decay. The clocks all come from one master
ratio (1.25 Hz = 800 ms), so they drift against each other. Three multisliders are written into `buffer~`s with `peek~`.
They're read back at audio rate with `index~` and used as continuous control signals.

## Where the port differs

- The paste held no preset or slider data, so the step, volume and filter values are made-up starting points.
- `grooveduck` isn't a stock Max object. It's emulated as a looper with a 1 ms fade at each loop point.
- A DC blocker sits before the output, because two voices add +0.9 offsets.
- In the original, `[/ 10.]` receives the tempo in both inlets and outputs 1. That pins the "0.125 Hz" voices at 1 Hz.
  The default keeps this behaviour, and a checkbox switches it to the intended tempo / 10.
